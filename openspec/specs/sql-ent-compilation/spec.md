# sql-ent-compilation Specification

## Purpose

Compiles easylist query plans into prepared PostgreSQL queries using ent's SQL builder without generated code, for applications that use ent and should not need another query library.

## Requirements

### Requirement: PostgreSQL contract with ent
The ent driver SHALL satisfy `contract-sql-postgres` and pass the shared conformance suite.

#### Scenario: Conformance suite
- **WHEN** the ent driver's tests run the conformance suite
- **THEN** every offline case passes, and every database case passes when `EASYLIST_PG_DSN` is set

### Requirement: No other query libraries
The ent driver package, without its tests, SHALL NOT import, directly or transitively, goqu, the query library of another easylist driver, or a PostgreSQL wire driver. Its tests MAY import more. It SHALL need no code generated by ent.

#### Scenario: Compiled-in packages
- **WHEN** the transitive imports of the ent driver package, without tests, are listed
- **THEN** they include ent packages and no goqu, bob, go-sqlbuilder, jet, gorm, or PostgreSQL wire driver package

### Requirement: Construction without configuration
The ent driver SHALL be constructed without arguments and SHALL hold no state between compilations.

#### Scenario: Shared value
- **WHEN** an application constructs the ent driver once and uses it in a runtime for every request
- **THEN** every compilation behaves as with a newly constructed driver

### Requirement: Bound pagination with ent
The ent driver SHALL bind limit and offset as arguments, never writing their values into the SQL text.

#### Scenario: Limit and offset values
- **WHEN** a page plan with limit 25 and offset 75 is compiled
- **THEN** the SQL text contains neither `25` nor `75` after `LIMIT` or `OFFSET`, and the last two arguments are `25` and `75`
