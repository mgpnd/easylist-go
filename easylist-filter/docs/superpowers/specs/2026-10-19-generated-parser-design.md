# Generated parser for `filter.Parse`: design

Date: 2026-10-19
Status: approved

## Goal

Make one grammar file the source of truth for the filter syntax, so the
documented grammar and the parser code cannot drift apart. Replace the
hand-written recursive-descent parser with one generated by goyacc from
`grammar.y`.

### Constraints

- Error positions (1-based byte offsets) stay identical for every input.
  Message wording may change.
- The public API is unchanged: `filter.Parse`, `Expr`, `Predicate`, `Logical`,
  `Literal`, `PredicateOp`, `LogicalOp`, `LiteralKind`, and all position
  accessors. easylist-sql-goqu needs no changes.
- The AST stays immutable and `Parse` stays safe for concurrent use.
- Third-party dependencies would be acceptable, but this design adds none.
  The generated code imports only the standard library, and `go.mod` is
  unchanged.

### Non-goals

- New language features (operators, literals, `NOT`, `NULL`, and so on).
- Any change to lexer behavior or lexer error messages.
- Moving token rules (quoting, case folding, number shape) into the grammar.
  They stay in `lexer.go` and as prose in `docs/query-language.md`.

## Approach

goyacc (`golang.org/x/tools/cmd/goyacc`) generates an LALR(1) parser from
`grammar.y`. The existing hand-written lexer stays and feeds tokens to the
generated parser.

Rejected alternatives:

- **pigeon (PEG), tokens and syntax in one file.** Farthest-failure error
  reporting changes positions (`1abc = 1` would report 1 instead of 2,
  `a = 1 AND (` would report end of input instead of the `(`). Keeping them
  needs error productions and backtracking-safe paren state in the grammar.
- **ANTLR4.** Needs Java to generate, adds the antlr4-go runtime, reports rune
  rather than byte offsets, and needs visitor boilerplate for the AST.

## Architecture

```
input ──lexFilter──▶ []token ──parseState (yyLexer)──▶ yyParse ──▶ Expr
       (lexer.go)              (parser.go)             (parser_gen.go, from grammar.y)
```

| File            | Role                                                              |
| --------------- | ----------------------------------------------------------------- |
| `grammar.y`     | New. Syntax rules and AST-building actions.                       |
| `parser_gen.go` | New, generated, committed. Imports only the standard library.     |
| `parser.go`     | `Parse`, the `go:generate` directive, `parseState`, the `tokenKind` to goyacc code table, error mapping. |
| `lexer.go`      | Unchanged.                                                        |
| `ast.go`        | Unchanged.                                                        |

Removed from `parser.go`: `parser`, `parseFilterSyntax`, `parseOr`, `parseAnd`,
`parseLogical`, `parsePrimary`, `parseGroup`, `parsePredicate`, `eofError`,
`peek`, `advance`, `predicateOps`, `literalKinds`.

### `grammar.y`

Plain left-recursive BNF. Left recursion gives left associativity, and the
`or_expr` / `and_expr` layering gives `AND` higher precedence than `OR`, so no
`%left` / `%right` declarations are used. The `BETWEEN STRING` restriction is a
grammar rule rather than a check in Go.

Rule skeleton (actions omitted):

```yacc
filter      : or_expr ;
or_expr     : and_expr | or_expr OR and_expr ;
and_expr    : primary | and_expr AND primary ;
primary     : predicate | '(' or_expr ')' ;
predicate   : IDENT ordinary_op value | IDENT BETWEEN STRING ;
ordinary_op : '=' | NEQ | '>' | GTE | '<' | LTE | CONTAINS | EXCLUDES ;
value       : STRING | NUMBER | BOOL ;
```

- `%union` carries `tok token`, `expr Expr`, and `op opAt` where
  `type opAt struct{ op PredicateOp; pos int }`. The `ordinary_op`
  alternatives produce an `opAt`; `value` produces a `Literal`-ready token.
- Actions build `*logicalNode` and `*predicateNode` exactly as today,
  including `operatorPos`, the field token, and `Literal{kind, text, pos}`.
- The `filter` action stores the root in the `parseState` (reached through
  `yylex`). A parenthesized group returns its inner expression; there is no
  group node.
- Token names in `%token` declarations are chosen with error display in mind;
  `parseState` maps them to user-facing names (see Error mapping).
- Amendment: the named tokens are `t`-prefixed (`tIDENT`, `tSTRING`, `tNUMBER`,
  `tBOOL`, `tNEQ`, `tGTE`, `tLTE`, `tCONTAINS`, `tEXCLUDES`, `tBETWEEN`,
  `tAND`, `tOR`) and so unexported, which keeps the constants goyacc generates
  for them out of the package API. The rule skeleton above and the error
  mapping below use the original unprefixed names; read them as the
  `t`-prefixed ones.

Generation, from a directive in `parser.go`:

```go
//go:generate go run golang.org/x/tools/cmd/goyacc@v0.49.0 -o parser_gen.go -p yy -v "" grammar.y
```

The version is pinned to `v0.49.0`, the newest `golang.org/x/tools` release
whose module requires `go 1.25.0`; v0.50.0 and later require Go 1.26 and would
force a toolchain download.
`-v ""` suppresses `y.output`. Consumers never run the generator.

### `parseState` (the yyLexer adapter)

`Parse` lexes the whole input first. A lexer error is returned as today and
takes priority over any syntax error. Then:

```go
type parseState struct {
	tokens []token
	next   int
	last   token // the most recent lookahead, for error positions
	atEOF  bool
	eofPos int   // len(input)+1
	open   []int // positions of '(' handed to the parser and not yet closed
	result Expr
	err    error // first error only
}
```

- `Lex` returns the goyacc code for the next token via a `tokenKind`-indexed
  table, stores the token in `lval.tok`, and records it in `last`. It pushes
  the position on `(` and pops on `)` when `open` is non-empty. At the end it
  sets `atEOF` and returns 0.
- `Error(msg)` records only the first error, mapped as described below.
- `Parse` returns `nil, err` on any error, otherwise `result, nil`.
- A fresh `yyNewParser()` and `parseState` are used per call.
  `yyErrorVerbose = true` is set once at package initialization, so no shared
  state is written while parsing.
- goyacc's value stack grows on demand, so deep nesting does not recurse.

### Error mapping

Rules, applied in order:

1. **Unclosed group at end of input.** If `atEOF` and `open` is non-empty,
   return `unmatched '(' at position P`, where P is the innermost entry. Every
   token has been handed to the parser by then, so the lexical paren stack
   equals today's parser stack.
2. **Stray `)`.** If the lookahead is a `)` handed to the parser while no `(`
   is open (tracked as `strayClose`), return `unmatched ')' at position P`.
3. **Otherwise**, reword goyacc's verbose message
   `syntax error: unexpected X[, expecting A or B ...]` as
   `unexpected X[, expected A, B, or C] at position P`. P is `last.pos`, or
   `eofPos` at end of input. Raw token names map to display names: `$end` to
   "end of input", `IDENT` to "field", `STRING` to "string", `NUMBER` to
   "number", `BOOL` to "boolean", operator tokens to their quoted spelling
   (for example `'!='`), keywords to their uppercase spelling.

goyacc lists expected tokens only when there are at most four, so some
messages become more generic than today. Approximate examples (the final text
is pinned in tests and in `docs/parser.md` during implementation):

| Input          | Today                          | After (approximate)                                 |
| -------------- | ------------------------------ | --------------------------------------------------- |
| *(empty)*      | expected predicate @1          | unexpected end of input, expected field or '(' @1   |
| `a 1`          | expected predicate operator @3 | unexpected number @3                                |
| `a BETWEEN 1`  | expected literal value @11     | unexpected number, expected string @11              |
| `a = )`        | expected literal value @5      | unmatched ')' @5                                    |
| `a = 1)`       | unmatched ')' @6               | unmatched ')' @6                                    |
| `a = 1 AND (`  | unmatched '(' @11              | unmatched '(' @11                                   |

Every error stays on one line and ends in `at position N`.

## Keeping docs and grammar in sync

- The grammar block in `docs/query-language.md` becomes the yacc rule skeleton
  shown above, in a `yacc` code block. It replaces the current (uncommitted)
  EBNF block. The sentence stating the grammar is LL(1) is removed.
- `TestGrammarDocMatchesYacc` reads `grammar.y`, takes the rules section
  (between the `%%` markers), strips `{ ... }` action blocks (brace-balanced,
  ignoring braces inside Go string and rune literals), normalizes whitespace,
  and compares the result rule by rule with the grammar block in
  `docs/query-language.md`. A mismatch fails the test.
- A new error-message table test pins the full message for every row of the
  `docs/parser.md` error table. The doc table is hand-mirrored from the first
  rows of that test and is updated together with it.

## Testing

- All existing tests stay unchanged and must pass: AST shape, operators and
  literals, grouping and associativity, 2,000-deep nesting, identifiers, and
  all of `lexer_test.go`. `TestParseSyntaxErrors` keeps checking position
  suffixes.
- New: `TestGrammarDocMatchesYacc` (above).
- New: the full-message error table (above), including the stray `)` and
  unclosed `(` cases.
- New: a concurrency smoke test that calls `Parse` from parallel goroutines,
  run under `go test -race`.
- Workspace check: `go test ./...` from the `go.work` root, so
  easylist-sql-goqu's tests run against the new parser. Its tests rely only on
  position suffixes and single-line errors.

## Documentation updates

- `README.md`: add a "Regenerate the parser" section (`go generate ./...`,
  commit `parser_gen.go`; a diff after regenerating means it was forgotten).
  The no-dependencies statement stays true.
- `docs/parser.md`: rewrite Stage 2 around `grammar.y`, `parseState`, how left
  recursion encodes precedence and associativity, and the three error rules.
  Update the error table and the "Extending the parser" steps (new token:
  lexer kind, `%token`, mapping table; new rule: `grammar.y`; then
  `go generate`).
- `docs/query-language.md`: the enforced grammar block, as above.
- `parser_gen.go` begins with goyacc's generated-code header so tools and
  reviewers skip it.

## Risks

- **Error wording regresses for some inputs** (for example `a 1`). Accepted;
  positions are what consumers depend on. goyacc `%error` directives in
  `grammar.y` could restore specific hints later without changing this design.
- **Stale `parser_gen.go`.** There is no CI, so freshness relies on the README
  instruction. The doc-sync test compares the doc with `grammar.y`, not with
  `parser_gen.go`, so it cannot detect a missed regeneration.
- **Verbose-message format.** Rule 3 parses goyacc's message text. The pinned
  goyacc version and the message table test keep this stable.
